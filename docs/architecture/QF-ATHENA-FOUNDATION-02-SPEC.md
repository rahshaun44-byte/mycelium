### Foundational Invariant

$$\boxed{ \text{Intelligence} \neq \text{Evidence} \neq \text{Verification} \neq \text{Truth} }$$

> **The Epistemic Quad-Separation**:
> 1. **Intelligence** ($\mathcal{I}$): The neural capacity to synthesize representations, hypothesize relationships, and propose derivations.
> 2. **Evidence** ($\mathcal{E}$): Traceable, hash-verified historical observations, literature excerpts, and experimental measurements.
> 3. **Verification** ($\mathcal{V}$): Mechanical validation via deterministic symbolic solvers, machine-checked proof kernels, or physical instrumentation.
> 4. **Truth** ($\mathcal{T}$): The objective state of physical reality, approached asymptotically but never guaranteed by neural output alone.
>
> *No proposition generated by an LLM shall receive scientific certification without independent verification and cryptographic provenance.*

## 3. Claim-Level Provenance Data Structures

### A. The Provenance Invariant
Every substantive proposition asserted by Athena must resolve to an immutable cryptographic tuple:
$$\text{Prov}(c_i) = \left\langle \text{doc\_sha256}, \text{chunk\_id}, [b_{\text{start}}, b_{\text{end}}], \text{source\_uri}, \text{MerkleProof} \right\rangle$$

### B. Distinction: Content Integrity vs. Source Authenticity

| Dimension | Verification Mechanism | What It Proves | What It Does NOT Prove |
| :--- | :--- | :--- | :--- |
| **Content Integrity** | SHA-256 Digest | Bytes match the exact uncompressed payload | Does not establish author identity or credibility |
| **Repository Identity** | TLS Certificate / GPG Commit Signature | Document was retrieved from official arXiv, PubMed, or repo | Does not verify the paper's scientific claims |
| **Author Provenance** | PGP / Keybase / Cryptographic Signature | Specific human author signed the release | Does not prove experimental reproducibility |
| **Physical Authenticity** | Hardware PCR / StrongBox Key Attestation | Sensor telemetry originated from authorized hardware | Does not prove sensor was properly calibrated |

## 4. Cryptographic Merkle Inclusion Verification

To verify that a specific claim $c_i$ or evidence span $s_j$ belongs to a validated document without loading the entire document into context:

1. **Leaf Construction**:
   A document is segmented into canonical sentence blocks $L_0, L_1, \dots, L_{n-1}$.
   $$H_i = \text{SHA256}(0x00 \parallel L_i)$$
2. **Tree Aggregation**:
   Parent nodes combine child pairs with a domain separation prefix:
   $$H_{\text{parent}} = \text{SHA256}(0x01 \parallel H_{\text{left}} \parallel H_{\text{right}})$$
3. **Audit Path**:
   A compact logarithmic proof $\pi_i = [A_0, A_1, \dots, A_{\lceil \log_2 n \rceil - 1}]$ allows verifying $L_i \in \text{Root}$ in $O(\log n)$ operations.
4. **Offline Verification**:
   The verifier recomputes the root hash from $L_i$ and $\pi_i$ and compares against the pinned `merkle_root` stored in SQLite.

## 6. Literature Ingestion & Decontamination Contracts

### A. Ingestion Sanitization
All raw external PDFs, arXiv LaTeX sources, and web preprints are treated as **untrusted data**:
- Stripped of executable macros, active embedded objects, and shell escapes.
- Isolated in an unprivileged scratch environment before parsing into UTF-8 markdown.

### B. Benchmark Decontamination Protocol
To eliminate test-set contamination (e.g., benchmark leakage into RAG chunks):
1. **Canonical Test Hashes**: Maintain a bloom filter and hash set of all questions across standardized benchmarks (GSM8K, MATH, HumanEval, ARC, MMLU).
2. **13-Gram Exact Match**: Scan every candidate document against benchmark $n$-grams.
3. **Jaccard Distance**: Compute token set overlap.
4. **Action**: If Jaccard similarity exceeds $0.10$ against any evaluation test set:
   $$\text{Status} \longleftarrow \text{QUARANTINED\_BENCHMARK\_LEAK}$$
   The document is strictly excluded from Athena's retrieval context during evaluation runs.

## 8. Epistemic Classification and Uncertainty Reporting

Athena decouples statistical confidence from empirical grounding.

### Multi-Dimensional Epistemic Vector
Every scientific conclusion outputs an epistemic state vector:
$$\mathbf{E} = \begin{bmatrix} p_{\text{softmax}} \\ \operatorname{sim}_{\text{vector}} \\ S_I \\ E_S \\ \text{Entropy}_{\text{semantic}} \end{bmatrix}$$

Where:
- $p_{\text{softmax}} \in [0, 1]$: Token generation confidence.
- $\operatorname{sim}_{\text{vector}} \in [-1, 1]$: Geometric similarity to retrieved chunks.
- $S_I \in [0, 1]$: Scientific theoretical importance.
- $E_S \in [0, 1]$: Replicated empirical physical evidence.
- $\text{Entropy}_{\text{semantic}} \ge 0$: Degree of semantic variation across temperature samples (hallucination indicator).

### Uncertainty Reporting Thresholds
- **High Epistemic Confidence**: $E_S \ge 0.80$, $\operatorname{sim} \ge 0.70$, $\text{Entropy} \le 0.15$.
- **Theoretical Formalization**: Verified by Lean 4 (M4) with explicit assumptions; empirical verification pending ($E_S = 0$).
- **Conjectural Hypothesis**: $\text{Entropy} > 0.35$ or $\operatorname{sim} < 0.45$. Automatically labeled:
  $$\text{"[EPISTEMIC BOUNDARY: Unverified hypothesis. Empirical grounding insufficient.]"}$$

## 9. OPA Admission Requirements (`epistemic_admission.rego`)

All scientific conclusions admitted into the Master Vault or used as prerequisites for system configurations must pass through Open Policy Agent gating.

```rego
package quantumflex.epistemic

default allow_vault_admission = false

# Rule 1: Mathematical results claimed as M4 or M5 must possess verified machine proof
allow_vault_admission {
    input.epistemic_tier in ["M4", "M5"]
    input.verification.verified == true
    input.verification.kernel in ["Lean4", "Coq", "SymPy"]
    input.verification.execution_time_ms > 0
}

# Rule 2: Empirical claims E4 or E5 must possess independent physical measurement provenance
allow_vault_admission {
    input.epistemic_tier in ["E4", "E5"]
    input.provenance.source_type == "physical_measurement"
    input.provenance.replications_count >= 2
    count(input.provenance.merkle_proof) > 0
}

# Rule 3: Theoretical models E1-E3 admitted only with explicit uncertainty bounds
allow_vault_admission {
    input.epistemic_tier in ["E1", "E2", "E3"]
    input.uncertainty.falsification_criteria_defined == true
    input.uncertainty.semantic_entropy_score < 0.40
}

# Rule 4: Fail-closed on contaminated literature
allow_vault_admission = false {
    input.decontamination.quarantine_status != "CLEAN"
}
```
